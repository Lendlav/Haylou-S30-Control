# S30 для Ubuntu

Небольшое нативное приложение C++/Qt для переключения ANC и встроенных пресетов EQ, а также для управления громкостью Bluetooth-аудиовыхода Ubuntu. Приложение не использует Python в работе, не содержит сетевого клиента, рекламы или аналитики. Команды гарнитуре отправляются только после нажатия «Применить».

При запуске приложение автоматически подключается к сопряжённым HAYLOU S30 по SPP, повторяет попытки каждые 8 секунд и восстанавливает соединение после обрыва. Ручное отключение приостанавливает автоподключение до следующего запуска или ручного подключения.

Одновременно разрешён только один экземпляр S30 для текущего пользователя. Повторный запуск при уже открытом окне завершается без создания второй копии; блокировка освобождается при закрытии приложения.

В шапке находится меню настроек оформления и языка. Доступны русский и английский переводы, включая статусы, сообщения об ошибках и подсказки; язык сохраняется между запусками. Темы: «Чёрный + натрий», «Лимонное золото», «Лёд и бирюза», «Медный янтарь» и «Winamp Classic». Выбранная тема сохраняется; в меню также указана версия 1.5. Нажатые кнопки визуально меняют глубину и цвет. Индикатор ANC отдельно подсвечивается зелёным для шумоподавления, жёлтым для прозрачности и красным для выключенного режима; цвет индикатора не зависит от темы. Состояние обновляется после подтверждённой команды и при входящем от наушников событии статуса `0x0E` (поле ANC `0x08`). Ярлык **HAYLOU S30** использует ту же жёлто-чёрную иконку с молнией, что и мобильная версия.

## Что выяснилось при исследовании

Исходная проблема была в канале Bluetooth-управления, а не в самом переключателе интерфейса. Соединение с RFCOMM-сокетом само по себе не означает, что выбран нужный сервис гарнитуры: старый Android-клиент открывал стандартный UUID `1101`, сокет сообщал об успешном соединении, но на команду не приходил ответ.

Официальный клиент HAYLOU S30 использует сервис UUID `0000FD3D-0000-1000-8000-00805F9B34FB`. Старый Ubuntu-клиент вместо обнаружения этого сервиса жёстко подключался к RFCOMM-каналу 10. Канал нужно узнавать через SDP-запись именно UUID `FD3D`: его номер не следует угадывать или фиксировать в программе. Теперь Ubuntu-приложение запрашивает SDP и подключается к найденному RFCOMM-каналу.

Вторая ошибка обнаружилась при повторной трассировке EQ: внутренний тестовый экран APK отправляет атрибут `0x08`, но обычный экран выбора пресетов использует `0xF2` (`SET_DEVICE_CONFIG`), config ID `7` (`HOP_CONFIG_EQ_MODE`) и код пресета. Ранее мы приняли команду тестового экрана за штатную; ACK от этой команды не доказывал, что DSP переключил пресет. Ubuntu-клиент теперь использует путь основного экрана. ANC по-прежнему отправляется через `0x08` с атрибутом `4`.

### Формат команд

Внешний пакет SPP имеет такой вид:

```text
AA BB CC | тип | команда | длина (2 байта, big-endian) | sequence | данные | DD EE FF
```

Для исходящего запроса тип равен `C0`; длина включает байт sequence и данные команды. Sequence увеличивается от запроса к запросу. Примеры:

| Действие | Данные команды | Пример полного кадра |
| --- | --- | --- |
| ANC выкл. | `02 04 00` | `AA BB CC C0 08 00 04 00 02 04 00 DD EE FF` |
| ANC | `02 04 01` | `AA BB CC C0 08 00 04 00 02 04 01 DD EE FF` |
| Прозрачность | `02 04 02` | `AA BB CC C0 08 00 04 00 02 04 02 DD EE FF` |
| EQ «Рок» | `03 00 07 02` | `AA BB CC C0 F2 00 05 00 03 00 07 02 DD EE FF` |

В ответе на успешную команду S30 возвращает статус `00` и тот же sequence, например:

```text
AA BB CC 00 08 00 02 00 00 DD EE FF
```

Приложение проверяет тип ответа, код команды, статус и sequence. ACK подтверждает, что команда обработана протоколом, но сам по себе не доказывает, что конкретный DSP-эффект слышимо изменился; поэтому важно отправлять именно команду основного UI, а не похожий тестовый запрос.

### Значения режимов

| Функция | Код | Значение |
| --- | ---: | --- |
| ANC | 0 | Обычный режим / ANC выключен |
| ANC | 1 | Шумоподавление |
| ANC | 2 | Прозрачность |
| EQ | 0 | Стандартный |
| EQ | 1 | Вокал |
| EQ | 2 | Рок |
| EQ | 3 | Классика |
| EQ | 4 | Поп |
| EQ | 5 | Бас |
| EQ | 6 | Саббас |
| EQ | 7 | Мягкий |
| EQ | 8 | Улица |

Пользовательский EQ в приложении намеренно отсутствует. Официальный клиент кодирует его отдельным значением `15`, но наушники отклоняют такую команду; настройка доступна только как встроенные пресеты `0–8`.

### Как проверили протокол

Локально изучен исходный код, декомпилированный из официального APK. Из него подтверждены UUID сервиса, построение кадра, коды ANC/EQ и способ подключения RFCOMM. Секреты или учётные данные для этого не требовались.

На телефоне с HAYLOU S30 старый UUID `1101` давал успешное открытие сокета, но после отправки ANC не было входящих данных. После переключения на `FD3D` гарнитура ответила успешным статусом на ANC. В первой версии мы также получили ACK на EQ-команды `0x08` из тестового экрана, но не подтвердили акустический эффект и ошибочно сочли это штатным способом. Повторная проверка обычного `DeviceVoiceViewModel` в APK показала, что реальный экран пресетов вызывает `BtDeviceEqSettingRequest`, который кодирует их как `0xF2` / config `7`. Именно этот формат теперь использует Ubuntu-приложение.

В официальном APK найдены и другие opcode. Ниже приведены имена из enum и классов запросов производителя; они показывают, что умеет библиотека приложения, но **не доказывают**, что каждая команда поддерживается прошивкой S30.

| Opcode | Имя/назначение в APK | Статус исследования |
| ---: | --- | --- |
| `0x02` | Чтение информации устройства | Запрос используется официальным приложением |
| `0x03` | Перезагрузка устройства | Объявлен; здесь не отправлялся |
| `0x04` | Уведомление телефона | Объявлен; формат и эффект для S30 не проверялись |
| `0x06–0x07` | Состояние/управление EDR | Объявлены; не проверялись |
| `0x08` | Установка атрибутов устройства | ANC использует этот путь; EQ-вариант найден во внутреннем тестовом экране |
| `0x09` | Чтение runtime-состояния | Используется официальным приложением для чтения параметров |
| `0x0A` | Установка дополнительного атрибута устройства | Объявлен; не проверялся |
| `0x0B` | Пробуждение Classic Bluetooth | Объявлен; не проверялся |
| `0x0C–0x0D` | Адрес и уведомления Bluetooth | Объявлены; не проверялись |
| `0x0E` | Отчёт о состоянии устройства | Такой opcode пришёл от наушников после ANC-команды |
| `0x0F–0x11` | Отвязка и уведомления A2F | Объявлены; не проверялись |
| `0x12` | Передача файла устройству | Объявлен; передача файлов не выполнялась |
| `0x13–0x14` | Чтение групповой информации и поддерживаемых функций | Объявлены; конкретные ответы S30 не проверялись |
| `0xD1` | Конфигурация режима EQ | Отдельный механизм; обычный экран встроенных пресетов его не вызывает |
| `0xF2–0xF3` | Запись/чтение общей конфигурации | Штатные пресеты EQ отправляются через `0xF2`, config ID `7` |

В коде производителя также перечислены статусы ответа: `0` — успех, `1` — ошибка, `2` — неизвестная команда, `3` — занято, `4` — нет ответа, `5–6` — ошибка CRC данных, `7` — неверный параметр, `8` — ответ превышает лимит, `9` — команда не поддерживается, `10` — частичная ошибка, `11` — устройство недоступно. Ubuntu-приложение сейчас обрабатывает статус успеха и коды отказа для тех команд, которые оно отправляет.

Сброс, отвязка, перезагрузка, прошивка и передача файлов из Ubuntu-приложения не выполняются. Названия opcode выше — карта исследованной библиотеки, а не инструкция посылать неизвестные кадры.

### Что означают Bluetooth-соединения

- A2DP передаёт звук. Ползунок громкости Ubuntu меняет громкость выбранного PipeWire/PulseAudio sink через `pactl`.
- SPP — отдельный Bluetooth Classic RFCOMM-сервис для настроек гарнитуры. Для него приложение использует UUID `FD3D` и находит RFCOMM-канал через SDP.
- Сопряжение нужно выполнить в настройках Ubuntu заранее. «Подключить» в приложении открывает канал управления; оно не выполняет сопряжение и не сканирует эфир.

В кадрах управления, разобранных из APK, нет прикладного шифрования, MAC/подписи или контрольной суммы внешнего кадра; используются framing, длина, sequence и статус. Официальный Android-клиент открывает RFCOMM через insecure API. Это не позволяет заключить, шифруется ли радиоканал на нижнем уровне: это зависит от Bluetooth link security и состояния сопряжения, а отдельного захвата радиообмена в этом исследовании не делали. Сопрягайте наушники с доверенным телефоном/компьютером и выключайте режим сопряжения после завершения.

## Сборка с нуля на Ubuntu 24.04

### 1. Установите инструменты

Откройте терминал и выполните:

```bash
sudo apt update
sudo apt install build-essential cmake ninja-build qt6-base-dev libbluetooth-dev bluez pulseaudio-utils
```

Эти пакеты дают C++-компилятор, CMake/Ninja, заголовки Qt6 и BlueZ SDP, `bluetoothctl`, а также `pactl`. На Ubuntu с PipeWire команда `pactl` работает через совместимый PulseAudio-интерфейс.

### 2. Сопрягите наушники

В системных **Настройки → Bluetooth** включите Bluetooth и выполните сопряжение с HAYLOU S30. Для проверки из терминала можно использовать:

```text
bluetoothctl
power on
agent on
default-agent
scan on
```

Когда появится адрес S30, выполните `pair XX:XX:XX:XX:XX:XX`, затем `trust XX:XX:XX:XX:XX:XX`, выключите поиск командой `scan off` и выйдите через `exit`. Подставьте адрес, показанный именно на вашей системе. Сброс наушников для сопряжения приложению не нужен.

Чтобы проверить, что гарнитура публикует сервис управления, выполните:

```bash
sdptool browse XX:XX:XX:XX:XX:XX
```

В записи должен присутствовать UUID, заканчивающийся на `FD3D`, и RFCOMM protocol descriptor с каналом. Программа находит канал автоматически при подключении.

### 3. Соберите исходники

Перейдите в корень каталога приложения — туда, где находятся `README.md`, `install-user.sh` и папка `native` — и выполните:

```bash
cmake -S native -B native/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build native/build --parallel
```

Готовый исполняемый файл появится в `native/build/HaylouS30Control`. CMake связывает приложение с системными Qt6 Widgets и `libbluetooth`; Qt и BlueZ не встраиваются в бинарник.

### 4. Установите приложение в меню текущего пользователя

Из корня каталога приложения выполните:

```bash
./install-user.sh
```

Скрипт берёт свежую сборку из `native/build`, копирует её в `~/.local/opt/haylou-s30-control`, устанавливает иконку в профиль пользователя и создаёт ярлык **S30** в `~/.local/share/applications`. Для установки в профиль пользователя права администратора не требуются. Чтобы сразу запустить без установки, используйте:

```bash
./native/build/HaylouS30Control
```

### 5. Управляйте наушниками

1. Запустите **S30** из меню приложений.
2. Нажмите **Обновить**, выберите сопряжённые HAYLOU S30 и нажмите **Подключить**.
3. Выберите режим ANC и нажмите его **Применить**.
4. Выберите встроенный пресет EQ и нажмите **Применить**.
5. Для громкости выберите Bluetooth-аудиовыход S30 и передвигайте ползунок: громкость меняется во время перемещения с коротким ограничением частоты команд. Это меняет громкость Ubuntu, а не пресет гарнитуры.

## Если не подключается или нет реакции

- **S30 отсутствует в списке:** проверьте сопряжение через настройки Bluetooth или `bluetoothctl devices`; затем нажмите **Обновить**.
- **SDP не находит UUID FD3D:** проверьте, что гарнитура включена и сопряжена; выполните `sdptool browse <адрес>` и убедитесь, что запись FD3D содержит RFCOMM protocol descriptor.
- **SDP проходит, но RFCOMM не подключается:** выключите и включите наушники, проверьте, что к ним не подключён другой телефон как управляющее устройство, и повторите подключение. Не подменяйте найденный канал числом `10` или каналом из другого Bluetooth-профиля.
- **Нет ползунка громкости:** подключите S30 как аудиоустройство в настройках Bluetooth, нажмите кнопку обновления списка выходов и проверьте `pactl list short sinks`.
- **Команда отклонена или истёк тайм-аут:** переподключите SPP и попробуйте один из встроенных режимов. Приложение показывает ошибку и не сообщает об успехе без подтверждения от гарнитуры.

Окно компактное по умолчанию (660×650), ограничено размерами (540–940 px по ширине, минимум 620 px по высоте) и центрирует область содержимого с максимальной шириной 900 px. При ширине меньше 720 px карточки располагаются в одну колонку, при большей — в две. Минимальная высота рассчитана на карточки без вертикальной полосы прокрутки. Сетевого подключения, аккаунта, доступа к файлам, контактам, микрофону или геолокации для управления не требуется.
