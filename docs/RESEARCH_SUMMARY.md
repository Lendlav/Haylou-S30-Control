# Сводка исследования HAYLOU S30

Дата фиксации: 2026-11-03. Это сводка ранее выполненных исследований и локально доступных артефактов. Она не утверждает, что физические измерения повторялись в рамках подготовки проекта.

## Что было неисправно в управлении

Первоначально приложения могли сообщать об успешном соединении с RFCOMM, но гарнитура не отвечала на команды или не меняла пресет. Причина состояла в выборе неверного сервиса/команды:

- S30 использует SPP UUID `FD3D`, а не стандартный Serial Port Profile UUID `1101`.
- Android-клиент должен открывать RFCOMM-сервис `FD3D`. Ubuntu-клиент сначала должен получить RFCOMM channel через SDP-запись этого UUID; фиксированный номер канала не надёжен.
- ANC-команда была определена верно: `0x08`, payload `02 04 <mode>`.
- Для штатных звуковых пресетов основное приложение производителя вызывает `BtDeviceEqSettingRequest`: `0xF2`, config ID `7`, payload `03 00 07 <preset>`. Команда `0x08` с payload `02 02 <mode>` обнаружена во внутреннем тестовом экране и не является штатным вызовом экрана пресетов. ACK на неё не доказывал изменения DSP.

После исправления формата ANC был подтверждён ответом S30; в истории эксперимента зафиксировано, что затем ANC и EQ-пресеты работали в Ubuntu, а код Android-клиента также обновили на `0xF2/config 7`. В этой фиксации мы не выполняли повторное подключение и не проверяли актуальное состояние телефона или наушников.

## Что умеют приложения

### Ubuntu

Нативный C++/Qt UI управляет ANC, встроенными EQ-пресетами и громкостью выбранного аудиовыхода PipeWire/PulseAudio. Для SPP используется BlueZ, UUID `FD3D` и поиск канала через SDP. Ползунок громкости меняет системный Bluetooth sink, а не громкость внутреннего DSP-пресета.

### Android

Java-приложение использует Android framework без сторонних библиотек. Оно управляет ANC и встроенными EQ-пресетами, регулирует media stream телефона и публикует MediaSession/foreground notification с контролами. Показ на экране блокировки зависит от разрешений и настроек Android. Приложение не сканирует эфир, показывает ранее сопряжённое устройство, не имеет разрешения на Internet и не выполняет OTA.

## Подтверждённые ограничения

- Пользовательский EQ с кодом `15` отклоняется S30; произвольные полосы не отправляются.
- Список команд производителя содержит больше opcode, чем используются приложениями. Наличие opcode в APK не доказывает поддержку устройством. Сброс, отвязка, reboot, file transfer и firmware update не выполнялись.
- Внешний кадр SPP, восстановленный по коду приложения, не содержит прикладной подписи/MAC или CRC. Отдельный захват радиоканала не проводился, поэтому состояние Bluetooth link encryption здесь не оценивалось.
- ACK подтверждает обработку на протокольном уровне, не обязательно слышимый результат. EQ был подтверждён именно сравнением правильного пути приложения и пользовательским наблюдением.

## История разработки приложений

1. Созданы независимые приложения вместо зависимости от официального приложения.
2. Ubuntu UI переведён на C++/Qt для малого размера; первоначальный layout исправлялся с учётом масштабирования/прокрутки.
3. Улучшена контрастность текста выпадающих списков; графический пользовательский EQ затем полностью удалён, поскольку устройство отклоняло настройку.
4. Исправлен выбор SPP endpoint: `FD3D` вместо `1101`; Linux выполняет SDP lookup канала.
5. Исправлен EQ: штатный путь `0xF2/config 7`, вместо команды тестового экрана `0x08`.
6. Android UI получил MediaSession/экран блокировки и те же исправленные команды; локальные APK и debug signing key не входят в проект.
