# Исследование прошивки и сигнала разряда батареи

## Что известно сейчас

Открытый репозиторий [LiteEMF/JL701n_earphone](https://github.com/LiteEMF/JL701n_earphone) содержит SDK и примеры для семейства Jieli JL701n/JL7018F. Локально исследован commit `0fe1a8a39ed9b205eaf6a7ca59e985205261a52b`. В нём не найдено упоминаний `HAYLOU S30`, `XP013`, `JL7018F6` или `LS_HD002`; этот SDK не является исходниками заводской прошивки S30. В корне проверенной копии не обнаружен LICENSE-файл, поэтому SDK не копируется и не включается в подготовленный проект.

FCC test report для сертифицированного образца перечисляет:

- маркировку `JL7018F6_HAYLOU S30_LS_HD002_V0.7_B1F12C06`;
- PCB обозначение `XP013_JL7018F-V1.2`;
- Bluetooth 5.4 и батарею 3.7 V / 600 mAh.

Это сведения с образца, описанного в отчёте; их нельзя автоматически отождествлять с ревизией конкретной пары пользователя.

## Зацепка из SDK: low-battery tone

В примере для `board_jl7018f_demo` код power warning вызывает `tone_play_index(p_tone->lowpower, 0)` и устанавливает повтор примерно раз в 60 секунд (`LOW_POWER_WARN_TIME`). При `CONFIG_USE_DEFAULT_SINE=1` `TONE_LOW_POWER` отображается на `sine_low_power`; в таблице примера есть компоненты 424 и 319 Hz. Демо-конфигурация платы задаёт `.lowpower = IDEX_TONE_LOW_POWER`.

В `user_cfg.c` примера `USE_CONFIG_STATUS_SETTING=1`; при старте конфигурация может считываться из `CFG_UI_TONE_STATUS_ID` и копироваться в структуру статусов. Это показывает, что в примере есть настраиваемая таблица UI-тонов. Оно **не доказывает**, что:

1. в S30 зашита такая же таблица или тот же код;
2. S30 разрешает её запись через поддерживаемую Bluetooth-команду;
3. отключение звука не затронет индикацию низкого напряжения или защитное выключение;
4. параметры SDK совпадают с заводскими порогами S30.

В том же примере `POWER_EVENT_POWER_LOW` отдельно инициирует выключение. Убирать защиту батареи ради отключения аудиосигнала нельзя; потенциальная цель исследования — только предупреждающий звук, сохраняя предупреждение/порог и штатное отключение.

## Почему пока нельзя безопасно перепрошить или патчить

- Нет подтверждённого дампа именно с пользовательских наушников и нет установленного способа чтения/восстановления их памяти.
- Не известны точный формат, подпись, контрольные суммы, адреса flash, bootloader, схема разделов и совместимость образа.
- Не получена полная заводская прошивка S30. Официальное Android-приложение получает package URL и MD5 и затем начинает штатную OTA-процедуру; простое нажатие «обновить» не является безопасным способом сохранить файл для анализа.
- FCC report доступен неполным локальным экземпляром: 35 страниц из заявленных 76; внутренних фото в локальном файле нет.
- Вскрытие корпуса/платы и подключение к неизвестным контактам может повредить наушники или батарею. Наличие UART/SWD/тестовых точек не подтверждено.

## Безопасный порядок будущего исследования

1. Сохранить текущую конфигурацию и состояние штатным способом; зафиксировать модель, серийные метки локально, не добавляя их в Git.
2. Найти официальный changelog и пакет прошивки через источник производителя. Сначала установить, может ли приложение обновить наушники автоматически и имеется ли официальный recovery/rollback.
3. Получить бинарный пакет без запуска установки только если предусмотрен документированный способ, который не инициирует OTA. Проверить происхождение и хэш; не модифицировать оригинал.
4. Изучать копию статически: формат, метаданные, подписи, разделы, кодеки/тоновые таблицы. Не подавать модифицированный пакет гарнитуре.
5. Для изменения звуков найти подтверждённую заводскую настройку конфигурации тонов или разобрать штатный образ. Сравнить механизмы SDK и S30; не переносить номера opcode/offset из демо.
6. До любого будущего аппаратного/firmware write иметь проверенный оригинальный дамп, план восстановления и внешний способ отключить питание. Если чтение и recovery не установлены, остановиться на статическом анализе.

## Источники исходного кода SDK

В локальном клоне, который не копируется в проект:

- `sdk/apps/earphone/power_manage/app_power_manage.c` — warning и отдельный power-low shutdown;
- `sdk/apps/earphone/include/app_power_manage.h` — период warning;
- `sdk/apps/earphone/tone_table.c` — таблица `sine_low_power`;
- `sdk/cpu/br28/tone_player_api.h` и `sdk/apps/earphone/include/tone_player.h` — отображение default sine;
- `sdk/apps/earphone/board/br28/board_jl7018f_demo.c` — пример выбора `IDEX_TONE_LOW_POWER`;
- `sdk/apps/earphone/user_cfg.c` — чтение status/tone config из syscfg.

Ссылки на инструменты Jieli приведены в [источниках](SOURCES.md). Прежде чем публиковать подробные выдержки из внешнего SDK или FCC-файла, проверьте лицензии и условия распространения.
